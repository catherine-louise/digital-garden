Understanding *features* and thinking about digital experiences as chains of features that are created and developed in particular ways might help shed light on why digital experiences feel the way that they do. 

## Defining "a feature"
The feature is how the design vision or concept—a fairy pack, an apartments pack, a family life pack—gets extruded into something that a large organization can design, build, and deploy.

Features are developed, identified, or ideated; shaped into briefs; iterated in user testing; prioritized and sequenced on roadmaps. Features are constrained. You cannot build a feature without some kind of existing architecture for it to hook onto. Features cost money to create: someone has to design the UI, specify how the feature should work, architect the way the code is written, write the code, and QA test the code. (And probably a lot else that I don't know because I'm not a product manager.) A feature is concrete and sometimes mind-numbingly technical. A feature can become untethered from the original problem it was trying to solve, or it can end up trying to solve way too many problems and be reused for too many different purposes. A feature is a long chain of telephone that starts with a design concept and ends with shipped code.
